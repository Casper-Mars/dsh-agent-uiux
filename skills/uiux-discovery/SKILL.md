# 定位：先想清楚，再动手

设计返工最大的来源不是画得不好，而是方向错了。本技能只做一件事：在动笔之前，
把「给谁、在什么场景、要什么气质、受什么约束」问清楚，落成一页 `design brief`，
让后面每一步都有据可依。

参考 `references/product-types.md` 判断产品类型与对应设计约束；填写 `assets/design-brief.md`。

## 第一步：判断该不该进设计流程

| 性质 | 判据 | 动作 |
|---|---|---|
| 修复 | 恢复既有预期行为，验收口径显然 | 不进设计流程 |
| 设计 | 新增界面、重做界面、改变结构 / 交互 / 信息层级 | 走本技能 → 设计系统 → 出图 |
| 需求 | 改变行为、范围或验收口径 | 回需求阶段，不在设计里决定 |

判据是**是否改变预期行为与结构**，不是改动行数。

## 第二步：问清五件事

不要一次抛一堆问题。按顺序问，能自己查的先自己查。

1. **产品类型**：B 端工具 / C 端应用 / 落地页 / 数据看板 / 内部系统。类型决定密度、导航与默认布局。
2. **用户与场景**：谁在用、多久用一次、在什么设备上、被打断还是专注。高频内部工具和一次性落地页是两种极端。
3. **目标**：这一版要解决的具体问题是什么？一句话说不清，说明还没到设计阶段。
4. **气质**：专业克制 / 亲和活泼 / 高端静谧 / 技术极客。给候选词，不逼用户报色号。
5. **约束**：品牌资产、技术栈、无障碍等级、必须兼容的设备、现成设计系统。

## 第三步：产出 design brief

按 `assets/design-brief.md` 填。合格标准：

- 每一条都能被后面某个设计动作验证（不是空话）。
- 明确写出「这次不做」，挡住范围蔓延。
- 气质写成可比对的形容词，后面 `uiux-pro` 才能据此推荐风格。

## 第四步：交接给下一段

- 方向定了 → 读 `uiux-pro` 选风格 / 配色 / 字体，或直接用 `uiux-design-system` 落 token。
- 结构还不清楚 → 先 `uiux-wireframe` 出低保真，再回来定视觉。
- 方向本身有争议 → 用 brief 里的候选与人拍板，不替人拍。

## 反合理化

| 借口 | 现实 |
|---|---|
| 先画两版给用户挑 | 没定方向就画，用户只会挑「看着顺眼的」，不解决真问题 |
| 用户没说，我就默认常规做法 | 默认做法有 80% 概率是 Inter + 紫渐变，那正是要避开的 |
| 时间紧，跳过定位 | 返工一次的时间够定位十次 |
| 气质太虚，没法落 | 虚的是没给候选；给 3 个可比对的形容词就具体了 |
