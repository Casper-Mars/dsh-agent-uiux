# 产品类型 → 设计约束速查

类型决定密度、导航、默认布局与视觉基调。先归类，再谈风格。

## B 端工具 / 内部系统

- 用户：高频、重复操作、目标明确、可培训。
- 密度：高。表格、批量操作、键盘快捷键优先。
- 导航：侧边栏 + 多级，突出「当前在哪」。
- 视觉：克制、低饱和、状态色语义清晰。信息 > 装饰。
- 重点：加载/空/错误/权限态齐全，效率高于美观。

## C 端应用

- 用户：低频、零培训、随时流失。
- 密度：中低。留白足、主操作醒目、一次只推进一步。
- 导航：底部 Tab 或单列流。
- 视觉：品牌感强，动效用于引导而非炫技。
- 重点：引导、空态转化、错误可恢复。

## 落地页 / Marketing 页

- 用户：带着一句话疑问「这跟我有关吗」，几秒内决定走或留。
- 结构：Hero 一句话价值 + 证据（截图/客户/数据）+ 行动召唤。
- 视觉：可以更张扬，字体与背景是记忆点；避免通用大路货。
- 重点：首屏说服力，移动端适配，加载性能。

## 数据看板 / Analytics

- 用户：需要「一眼看出异常」。
- 结构：概览 → 下钻。KPI 卡 + 趋势 + 分布。
- 视觉：图表色需可区分且色盲友好，数字用等宽/表格数字。
- 重点：空数据、加载中、口径说明、导出。

## 移动 / 原生 App

- 约束：触控目标 ≥ 44×44，拇指热区，断点重排不是缩放。
- 视觉：系统级动效与手势契合平台习惯。
- 重点：状态（下拉刷新、骨架屏、离线、权限弹窗）。

## 设计系统 / 组件库本身

- 用户：开发者与其他设计师。
- 结构：token → 组件 → 模式 → 文档。
- 重点：命名稳定、变体穷举、每个组件标状态与可访问性。
