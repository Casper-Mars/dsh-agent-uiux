# 线框：先定结构

线框图故意去掉颜色与品牌，让讨论聚焦在**布局、信息层级、交互流程**，
而不是「这个蓝色好不好看」。输出为黑白 SVG 或可查看的页面。

画法约定见 `references/wireframe-guide.md`；每屏规格按 `assets/wireframe-spec.md` 填。

## 原则

1. **黑白 + 灰度**：只用黑、白、1–2 档灰。不放真实图片，用占位框 + 对角线。
2. **真实文案优先**：用真实或接近真实的文字，不用 lorem ipsum，否则发现不了内容长度问题。
3. **一个屏只讲一件事**：主操作醒目，次要操作降级。
4. **标注层级**：用编号或标签标出信息区块与交互点，方便讨论。
5. **穷举状态**：至少 default + empty + loading + error 各一张骨架。

## 流程

1. 读 `design brief`（没有先 `uiux-discovery`），确认产品类型与关键场景。
2. 列出这一批要画的屏与流程（入口 → 步骤 → 分支 → 退出）。
3. 每屏按 `references/wireframe-guide.md` 布局：导航 / 主内容 / 辅助 / 主操作。
4. 用 SVG 输出，按 `assets/wireframe-spec.md` 写规格说明。
5. 标注哪些点需要后面定视觉、哪些是结构决策（要人拍板）。

## 输出与交接

- 产物放 `design/wireframes/<screen>.svg` + `design/wireframes/<screen>.md`（规格）。
- 线框确认后再进 `uiux-design-system` / `uiux-prototype`。
- 不要把线框当最终稿；它的使命是把结构对齐。

## 反合理化

| 借口 | 现实 |
|---|---|
| 直接上高保真更快 | 没对齐结构就上色，改一次色板比改十次布局都便宜不了 |
| 先放 lorem 占位 | 真实内容长度会暴露布局问题，占位会掩盖 |
| 线框不用标交互 | 不标的话讨论会飘回「好不好看」 |
| 只有 default 就够 | 空/加载/错误恰恰是线框最该先想清的 |
